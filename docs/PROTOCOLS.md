# CAN 路由与上报协议

[返回项目首页](../README.md) · [架构](ARCHITECTURE.md) · [构建](BUILD_AND_TEST.md) · [验证](VERIFICATION.md)

字段以 [`can_cache.c`](../firmware/src/can_cache.c)、[`can_cache.h`](../firmware/include/can_cache.h) 与 [`eth_rmii.c`](../firmware/src/eth_rmii.c) 为准。
本文描述现有线格式与业务分组，不表示已实现完整 J1939、时间同步或上位机协议栈。

## 1. 总线配置与长度

| 总线 | `bus` | 标称目标速率 | 数据段目标速率 |
| --- | --- | --- | --- |
| CAN1 / FDCAN1 | 0 | 500 kbit/s | 2 Mbit/s |
| CAN2 / FDCAN2 | 1 | 1 Mbit/s | 5 Mbit/s |

速率与 80% 采样点为配置目标；计算与寄存器模型检查不等于波形测量。
`fdcan_frame_t.dlc` 是原始 DLC 编码，`can_report_rec_t.dlc` 是转换后的负载字节数。

以下为 CAN FD 数据帧的长度映射：

| 原始 DLC | CAN FD 负载字节数 |
| --- | --- |
| 0～8 | 与 DLC 相同 |
| 9 | 12 |
| 10 | 16 |
| 11 | 20 |
| 12 | 24 |
| 13 | 32 |
| 14 | 48 |
| 15 | 64 |

CAN FD 映射函数为 `fdcan_dlc_to_bytes()`。
实际收发与上报统一调用 `fdcan_frame_payload_bytes()`：Classic CAN 数据帧取 `min(DLC, 8)`，RTR 远程帧负载为 0。
原始 DLC 保留在 `fdcan_frame_t`，TLV 的长度字段写入实际负载字节数。
接收队列按值保留完整帧，解析后将总线来源、标志和字节数写入上报记录。

## 2. 过滤规则

规则定义在 [`fdcan_filter.c`](../firmware/src/fdcan_filter.c)。
`fdcan_filter_route()` 按表顺序选择首次匹配结果。
标准与扩展 ID 分开匹配，默认未匹配帧拒收。
下表“优先标记”指过滤元素硬件语义，不等于 P0/P1/P2 业务优先级。

### CAN1

| 类型 | 匹配 | 目的地 | 优先标记 |
| --- | --- | --- | --- |
| 标准范围 | `0x080..0x0FF` | FIFO0 | 否 |
| 标准掩码 | ID `0x100`，掩码 `0x7F0`，即 `0x100..0x10F` | FIFO0 | 否 |
| 标准双 ID | `0x200` / `0x201` | FIFO1 | 是 |
| 标准范围 | `0x400..0x47F` | FIFO1 | 是 |
| 标准双 ID | `0x700` / `0x701` | FIFO1 | 否 |
| 扩展掩码 | ID `0x18FF0000`，掩码 `0x1FFF0000` | FIFO0 | 否 |
| 扩展范围，不应用 XIDAM | `0x0A000000..0x0A0000FF` | FIFO1 | 是 |

### CAN2

| 类型 | 匹配 | 目的地 | 优先标记 |
| --- | --- | --- | --- |
| 标准范围 | `0x300..0x37F` | FIFO0 | 否 |
| 标准双 ID | `0x580` / `0x581` | FIFO1 | 是 |
| 标准范围 | `0x080..0x0FF` | FIFO0 | 否 |
| 标准双 ID | `0x400` / `0x401` | FIFO1 | 是 |
| 扩展精确掩码 | `0x1FFFFFFF`，掩码 `0x1FFFFFFF` | FIFO1 | 是 |
| 扩展范围，不应用 XIDAM | `0x0A000000..0x0A0000FF` | FIFO1 | 否 |

实际规则数为 CAN1 标准 5 / 扩展 2，CAN2 标准 4 / 扩展 2。
配置中的更大过滤器数量常量不是当前装载条数。

### GFC 与嗅探

`fdcan_filter_gfc_value()` 编码 GFC 未匹配动作：

| ANFS/ANFE 编码 | 未匹配帧动作 |
| --- | --- |
| 0 | FIFO0 |
| 1 | FIFO1 |
| 2 | 拒收 |
| 3 | 拒收 |

默认 ANFS=2、ANFE=2，RRFS/RRFE=0，GFC 为 `0x28`。
嗅探启用后 ANFS/ANFE 改为 0；关闭后恢复默认拒收。
`hal_sim_fdcan_inject()` 读取当前 GFC，保证注入路径响应切换。
运行时切换通过 INIT/CCE 配置窗口更新 GFC，并恢复原运行/停止状态。
驱动返回 0 / -1 / -2 / -3，分别表示成功、参数错误、失败且恢复成功、恢复失败。
应用仅在两路成功后更新嗅探标志；任一路失败都会返回错误，并尝试恢复原过滤配置。
调用方需串行化配置与恢复操作，详细流程见 [架构说明](ARCHITECTURE.md)。
此模式仅放宽接收，不是已验证的 CAN 静默监听模式。

过滤元素 FEC 使用另一套编码：FIFO0=1、FIFO1=2、拒收=3、FIFO1+优先标记=6。
不能将 FEC 值直接当作 ANFS/ANFE 值。

## 3. 业务优先级与出队

`can_cache_prio_of_id()` 定义独立于 FIFO 路由的业务优先级：

| ID 类型 | 范围/ID | 业务优先级 |
| --- | --- | --- |
| 标准 | `0x400..0x47F`、`0x580..0x5FF` | HIGH=2，P0 |
| 标准 | `0x080..0x1FF`、`0x200..0x27F`、`0x700` | MID=1，P1 |
| 标准 | `0x300..0x37F` 及其他 | LOW=0，P2 |
| 扩展 | `0x0A000000..0x0A0000FF` | HIGH=2，P0 |
| 扩展 | `0x18FF0000..0x18FFFFFF` | MID=1，P1 |
| 扩展 | 其他 | LOW=0，P2 |

例：CAN2 的 `0x1FFFFFFF` 帧命中 FIFO1 优先过滤器，但业务缓存仍为 LOW。
规则只决定 ID 分组，不包含完整设备报文负载解码。
“SYNC”分组名不证明已实现时钟同步。

缓存先 P0，再 P1，最后 P2；每层 FIFO。
跨优先级发送顺序不是全局接收顺序，消费者应参考 `seq` 与时间戳并处理复位。
容量为 64/256/512；高优先级满也会淘汰旧高优先级记录。

## 4. TLV 批次头

`CAN_PACK_HEADER_BYTES=8`。
所有偏移从 UDP 应用负载起点计，整数显式序列化为小端。

| 偏移 | 大小 | 字段 | 当前值/语义 |
| --- | --- | --- | --- |
| 0 | 1 | `version` | `H750_REPORT_VERSION=1` |
| 1 | 1 | `node` | `H750_NODE_ID=0x21` |
| 2 | 2 | `count` | 记录条数，LE16 |
| 4 | 4 | `batch` | 组包调用计数，LE32 |

`batch` 使用递增前的 `cache.pack_calls`，第一次为 0。
缓存重新初始化或 `can_cache_reset()` 后计数重置。
空组包调用也可增加该计数，不能把它当作永久唯一包号或远端确认号。

## 5. 单条记录 TLV

紧接批次头写入若干 TLV：

| TLV 相对偏移 | 大小 | 字段 |
| --- | --- | --- |
| 0 | 1 | `type=0x01`，`CAN_TLV_TYPE_RECORD` |
| 1 | 1 | `len=16+payloadBytes`，不含这 2 字节 TLV 头 |
| 2 | `len` | 记录值 |

记录值的固定部分为 16 字节，以下偏移相对记录值起点：

| 值内偏移 | 大小 | 字段 | 语义 |
| --- | --- | --- | --- |
| 0 | 4 | `can_id` | LE32；标准/扩展类型由标志区分 |
| 4 | 1 | `flags` | XTD/FDF/BRS/ESI/RTR/FIFO1 |
| 5 | 1 | `payloadBytes` | 0～64 的字节数，不是原始 DLC 编码 |
| 6 | 1 | `bus` | 0=CAN1，1=CAN2 |
| 7 | 1 | `priority` | 0=LOW，1=MID，2=HIGH |
| 8 | 4 | `ts_us` | LE32；解析阶段本地微秒时基 |
| 12 | 4 | `seq` | LE32；累计解析序号，应用重置后重置 |
| 16 | 0～64 | `data` | 原始负载字节 |

上报中的字节 6、7 已用于总线和优先级，并非空白保留字段。
内存中的 `can_report_rec_t` 字段排列与线格式不同，不能直接发送结构体。
`CAN_TLV_TYPE_STATS=0x02` 已定义，但当前组包函数不输出统计 TLV。

### 标志位

| 位 | 常量 | 含义 |
| --- | --- | --- |
| 0 | `CAN_REC_FLAG_XTD` | 扩展 ID |
| 1 | `CAN_REC_FLAG_FDF` | CAN FD |
| 2 | `CAN_REC_FLAG_BRS` | 数据段变速 |
| 3 | `CAN_REC_FLAG_ESI` | 错误状态指示 |
| 4 | `CAN_REC_FLAG_RTR` | 远程请求 |
| 5 | `CAN_REC_FLAG_FIFO1` | 来自 FIFO1 |
| 6、7 | 未定义 | 当前应用清零 |

过滤索引、`anmf`、`hp` 和原始硬件 `rx_ts` 不在当前 TLV 中。
`ts_us` 不是 UTC，也不表示带跨节点同步保证的物理接收时间。

### 构造示例

以下是按字段表构造的示例，不是抓包或本次测试导出的原始字节。
内容为 CAN2 标准 ID `0x400`，FIFO1，FD+BRS，HIGH，2 字节 `AA 55`，本地时间 1000 µs，序号 1。

```text
01 21 01 00 00 00 00 00    # 批次头：版本1，节点0x21，1条，批次0
01 12                      # TLV：记录类型，值长度18
00 04 00 00 26 02 01 02    # ID、flags、字节数、bus、priority
E8 03 00 00 01 00 00 00    # ts_us=1000，seq=1
AA 55                      # 数据
```

总长为 28 字节：8 字节批次头 + 2 字节 TLV 头 + 18 字节记录值。

## 6. 组包触发与容量

`can_cache_should_flush()` 检查 P0 非空或总水位 ≥ 700‰。
`app_report_step()` 增加 20 ms 周期条件。
这三个条件为“或”关系，触发后还要等应用阶段被调度。
不应宣称严格 20 ms 端到端时延保证。

单个应用负载最大 1400 字节。
单条记录长度为 `2+16+payloadBytes`，包总长为 `8+Σ记录长度`。
若全是 64 字节负载，最多容纳 16 条：`8+16×82=1320`。
若全是 8 字节负载，最多容纳 53 条：`8+53×26=1386`。
这些是格式计算，不是吞吐量或传输效率实测。

## 7. Ethernet / IPv4 / UDP 封装

`eth_build_udp_ipv4()` 构建外层，`eth_send_report()` 使用固定配置发送。

| 字段 | 当前实现 |
| --- | --- |
| 源 MAC | `02:00:00:48:37:50` |
| 目的 MAC | `FF:FF:FF:FF:FF:FF`，链路广播 |
| 源 IPv4/端口 | `10.0.0.33:50000` |
| 目的 IPv4/端口 | `10.0.0.1:50001` |
| EtherType | `0x0800` |
| IPv4 | IHL=5，TTL=64，协议=17，DF=`0x4000`，ID=1 |
| IPv4 头校验 | `eth_ip_checksum()` 计算 |
| UDP 校验和 | 0，不计算 UDP 校验 |
| Ethernet 头 | 14 字节 |
| IPv4 头 | 20 字节 |
| UDP 头 | 8 字节 |
| TLV 起点 | 原始帧偏移 42 |

外层整数使用大端网络字节序，内层 TLV 多字节整数使用小端。
最短原始帧补齐至 60 字节，不含 FCS。
1400 字节 TLV 对应 1442 字节原始帧，不含 FCS。
IPv4 目的地址固定，不意味着代码执行了 ARP 单播解析。
当前不提供 ARP、DHCP、TCP、TLS、完整 IP 栈或接收端程序。
`eth_set_loopback()` 是进程内队列回环，不是外接网线的网络验证。

## 8. 交付与解析边界

- 组包先消费缓存，UDP 本地发送失败时无 ACK/重入队/重传。
- 成功计数表示本地发送函数接受，不证明接收端交付。
- 业务缓存溢出和接收队列满都可能丢失。
- 序号和批次号非持久化，复位、回绕与跨节点冲突需由接收端处理。
- 协议没有应用层 CRC、身份认证、加密、时钟同步或确认机制。
- `can_cache_unpack_tlv()` 是往返自检工具，不是已加固的网络入口。

解包函数没有完整校验版本/节点。
它也未在复制前完整验证 `len >= 16 + payloadBytes`，畸形声明仍需加固。
接收不可信数据前，应新增严格边界校验与负向测试，不能仅以正常往返测试作为安全依据。

## 9. 心跳与文件导出

`app_heartbeat_step()` 每 1000 ms 尝试从 CAN1 发送 ID `0x700`，FD+BRS，8 字节。
前两个字节为接收数低 16 位的小端形式，第 2 号字节为上报包数低 8 位，第 3 号字节为标记 `0x01`。
剩余字节初始化为 0；该心跳不是主机 UDP 接收确认。

`diag.log` 为 `diag_log_dump_text()` 导出的文本。
`offline.csv` 每行只包含 `priority,can_id`，CAN ID 使用十进制。
该 CSV 不包含 CAN 数据、总线、时间戳或序号，不是完整数据备份格式。
导出会消费缓存，文件写失败也没有回滚保证。
